# 数据库拥堵与登录恢复验证

## 修复范围

- 将无效 JWT 与数据库查询失败分开：连接池排队满返回繁忙，不清登录 Cookie，也不使用旧鉴权结果放行。
- 用户与有效会话的正常鉴权读取由两次 SQL 合并为一次；多设备登录配置过期读取合并在途请求。
- 主机指标、流量及指标订阅的权限校验改为批量读取，仍实时检查所有权、手动权限和有效套餐权限，不缓存授权结果。
- 鉴权读取最多 8 个并发、256 项排队、最长等待 2 秒；展示加载最多 8 个并发、64 项排队、最长等待 1.5 秒。执行中的 SQL 保留槽位直至真正结束。此限制不是全局数据库连接数或硬性预留连接。
- 主要实时页面读取失败后按 5/10/20/30 秒退避，保留已有数据；恢复后返回原刷新频率。首次鉴权暂时失败不跳登录，自动重试验证。
- Agent presence / heartbeat 遇到数据库拥堵返回 503 与重试提示，繁忙日志每分钟最多一条，不再逐请求输出堆栈。

## 故障注入

使用真实 SQLite 数据库、JWT、鉴权上下文和 Agent 路由验证：

- 原样注入 `Queue limit reached.`、嵌套驱动异常和未知查询异常：请求拒绝访问，但 Cookie 不清除，恢复后同一凭证可用。
- 阻塞数据库约 2.2 秒并发送 320 个鉴权请求：8 个进入驱动等待，312 个被有界队列拒绝或超时，清除 Cookie 数为 0；释放阻塞后恢复。这是过载保护验证，不是 320 个请求全部成功的容量证明。
- 撤销会话、禁用账号仍拒绝访问；无效 JWT 仍正常失效。
- Agent presence / heartbeat 拥堵返回 503，presence 恢复后返回 200；数据库健康状态不因排队满被标为断开。

## 初版修复的本地 SQLite 验证

下表为早期修复版（鉴权 4 并发、64 项排队、1.5 秒等待）的记录。远程实测后，最终版本扩大了应用层鉴权等待队列并增加批量主机权限校验；不能将下表视为最终版本的对照性能。

## 远程 2 核 2G MySQL 对照

服务器为 Debian 13、2 核、约 1,974 MiB 内存，原有 aaPanel、MySQL 5.7 与 Agent 保持不变。测试独立启动 MySQL 8.0.46，实际核验 `innodb_buffer_pool_size=134217728`（128 MiB）、`max_connections=64`；面板连接池仍为 16，没有调大。

为避让现有服务，面板与发压端共用 1.25 核、512 MiB 容器限额，测试 MySQL 使用 0.5 核、768 MiB 容器限额。注意容器内存限额不等于 InnoDB 缓存大小。首次使用 512 MiB 的 MySQL 容器曾 OOM，该轮不作为最终对照；提高测试容器限额后，前后版本均重新运行，最终三只容器均无 OOM。

基线为 `7a6f1cb` 的后端代码，修复版为本次工作区代码。使用 3 个普通账号、9 个模拟 Agent、57 条规则；1/10/25/50 表示同时打开的模拟页面数，不代表同数量独立用户。每个页面每轮并行请求鉴权、主机状态、指标、流量、规则分页、规则汇总和规则流量，完成后等待 2 秒；每阶段约 15 秒，不是无间断发压。9 个模拟 Agent 同时发送 presence 与完整心跳。

| 并发页面 | 基线页面 P95 | 修复版页面 P95 | 基线 / 修复版 SQL 次数 | 基线 / 修复版页面失败数 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 346 ms | 195 ms | 1,089 / 691 | 0 / 0 |
| 10 | 938 ms | 296 ms | 4,795 / 2,411 | 0 / 0 |
| 25 | 2,238 ms | 741 ms | 6,926 / 3,847 | 0 / 3 |
| 50 | 4,205 ms | 1,767 ms | 9,685 / 5,253 | 0 / 0 |

由于每轮等待在请求完成后开始，较快版本在同一时间内能完成更多轮次；表中 SQL 总次数不是等请求数量的单请求对照。50 页面阶段，基线完成 1,092 次页面请求，修复版完成 1,820 次；驱动队列峰值从 157 降为 27。各常规阶段 Agent 请求均无错误，50 页面阶段 Agent P95 从约 4,007 ms 降为 1,637 ms。

修复版 25 页面阶段的 3 次失败进一步核对为 `ECONNRESET`，不是 503 或 SQL 错误；具体触发原因未定位，不能把这轮描述为全程零失败。真实浏览器的 HTTP 批处理、轮询退避、加密 Agent 传输和真实转发数据面没有在此发压端中模拟。测试短、前后顺序固定且共享同一隔离数据库，不将结果视为长期容量保证。

### 真实连接池故障

占用面板全部 16 条连接约 2.2 秒，发起 320 次真实 Cookie 鉴权请求：

- 基线：53 次清除 Cookie，并返回 `auth.me=null`；另有 11 次连接重置。说明 HTTP 200 也不能证明登录链路正常。
- 修复版：0 次清除 Cookie、0 次匿名降级，288 次明确返回繁忙，其余请求在连接恢复后成功；原 Cookie 恢复检查返回 200。故障期间返回繁忙是有界过载保护，不是全部请求成功。
- 两个版本的禁用账号与撤销会话校验均拒绝访问。优化没有放宽安全校验。

最终结果保存在本地忽略目录 `dist/load-test/remote-mysql-baseline-final.json` 与 `dist/load-test/remote-mysql-fixed-final.json`。临时数据库与数据、容器、网络、下载镜像和远程测试目录在取回结果后清理；原有服务不改动。
