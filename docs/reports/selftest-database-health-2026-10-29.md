# 点击链路探测后数据库误报不可用

日期：2026-10-29。修复暂存本地，未升级版本、未发布。

## 核实结果

用户指出的“本地连接池错误污染全局健康状态”成立，但还有一个更直接的触发原因：自测后台清理任务继承了创建自测的事务上下文。

1. 隧道测试、规则经隧道测试和转发链测试会在事务中创建自测记录。
2. `createForwardTest()` 调用 `selfTestSweepActivity.markActive()`，同步通知清理任务创建定时器。
3. 原定时器继承调用方的 `AsyncLocalStorage` 事务上下文。
4. 事务提交、连接释放后，定时器仍通过 `queryRaw()` 使用这条已释放的连接，而非重新向池申请连接。
5. 守卫合成 `PROTOCOL_CONNECTION_LOST: Database connection is closed`；`reportDatabaseErrors()` 将其提交给全局数据库健康状态。
6. 面板因此进入数据库不可用页面，等待健康检查恢复。这不需要 MySQL 服务发生故障，也不一定需要连接先超时：正常释放事务连接即可触发。

## 修复

- 将自测清理回调绑定到创建调度器时的异步上下文，避免被触发它的请求/事务污染。后续重排定时器、空闲后再次唤醒同样隔离。
- 守卫对已释放连接使用独立的 `DatabaseLeaseClosedError` / `DATABASE_LEASE_CLOSED`，不再冒充数据库驱动的协议断连。
- 全局健康分类不将此本地错误视为数据库掉线；真正的驱动断连、拒绝连接、认证失败仍保持原有故障处理。
- HTTP、tRPC 和会话解析对此类异常返回安全的请求级繁忙提示，不泄露 SQL，不清除登录凭证，也不绕过权限校验。
- 保留初始化失败的阻断行为；不自动重放结果不确定的写入或事务。

## 验证方法

`server/forwardTestDispatch.test.ts` 新增 MySQL / PostgreSQL 回归测试：使用实际事务封装、实际自测仓库和实际定时器，驱动连接使用测试替身，不依赖外部数据库。

修复前，两条测试均复现原错误：

```text
[DatabaseHealth] unavailable type=mysql code=PROTOCOL_CONNECTION_LOST
{ code: 'PROTOCOL_CONNECTION_LOST', message: 'Database connection is closed' }
```

修复后，两条测试均通过：后台任务没有继承事务、独立申请连接、数据库全局状态保持健康。

其他回归覆盖：

- 已释放、已过期及驱动实际调用前释放的连接，不能继续执行 SQL。
- 守卫本地错误及其包装不会触发全局不可用；真正驱动错误不会被屏蔽。
- HTTP / tRPC 失败只影响当前请求，其他 API 仍可访问。
- Cookie 和 Bearer 会话遇到此错误保留凭证，但验证失败时不得授权。
- 定时器首次激活、窗口结束和再次激活保持调度器上下文；原防重叠及空闲停机行为不变。

这确认了代码中可复现的触发链，不代表对用户服务器做过在线验证，也不排除其他独立的数据库故障。

验证结果：针对性测试 62 项、自测流程测试 53 项、后端主测试 779 项及性能回归测试 45 项均通过（不同测试组存在重叠）；TypeScript 类型检查、服务端构建及 `git diff --check` 通过。本次没有修改 Agent、移动端或数据库结构。
