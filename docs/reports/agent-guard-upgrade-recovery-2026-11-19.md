# Agent 升级后 Guard 限速恢复验证（2026-11-19）

## 问题与修复

Guard 是 Agent 进程内的 TCP/UDP 代理和限速组件。升级、重启 Agent 会使这些监听器消失；磁盘规则标记和独立转发后端可能仍存在，不能仅凭旧的运行标记判断限速已经生效。

排查发现两条恢复缺口：

- 运行中的进程后端 Guard 会进入期望状态核对，但 iptables/nftables 不在该分支中。首次本地运行快照尚未提供时，已有规则的 `isRunning` 可能使恢复动作被省略。
- 即时 SSE 配置推送仅携带期望动作、运行规则及延迟探测，没有 Guard 配置；Agent 处理该推送也没有同步 Guard，依赖后续完整心跳补上。

现在所有受支持的 Guard 规则均参与核对。SSE 带上完整 Guard 配置及签名，Agent 在后端动作完成后同步 Guard，完整心跳继续作为补充。健康监听器仍通过原有幂等检查复用，限速调整原位更新；旧面板省略 Guard 字段时保留当前状态，明确的空列表才移除 Guard。面板和 Agent 需配套更新。

未更改逐规则限速口径、版本号或安装器。云端用替换 Agent 可执行文件并重启的方式验证升级后的进程恢复，未运行完整一键升级安装脚本。

## 自动回归

真实 SQLite 和 HTTP 心跳验证覆盖 iptables、nftables、Realm、socat、Nginx 五种端口转发后端：

- 数据库中已有规则保持运行标记，Agent 版本变化且尚未提供首份本地运行快照时，仍生成 Guard 核对动作和上下行限速配置。
- 解密真实 SSE 事件，确认其携带的 Guard 配置、签名与完整心跳一致。
- 重启后只有 Guard 规则标记、没有实际就绪监听器时，返回修复动作。
- 停用的规则和未限速的内核规则不新增 Guard。

分别临时恢复旧的内核核对条件、旧的 SSE 载荷后，新增回归均按预期失败；恢复修复后通过。Agent 回归另外确认 SSE 原位修改双向速率、兼容省略字段及明确空列表删除。

专项 56 项、完整服务端回归 841 项均通过；`go test ./...`、TypeScript 类型检查、服务端构建和文档构建通过。
