# GOST 固定出口端口复用云端验证（2026-11-19）

## 变更与环境

同一条 GOST 隧道下的多条规则改为连接隧道配置的固定出口端口，经过认证的 Relay 为每条连接携带目标地址。每个出口节点保留一个隧道监听器，新增业务规则不再分配随机出口公网端口。六种 GOST 传输模式均采用此方式，Nginx Stream 的端口分配约定保持原有行为。

本次候选基于提交 `52bd6cbd712807153b2d80f780be3b7d835ce421` 的工作区改动，未更新版本号、未发布。测试在用户授权的 Linux 云服务器中建立独立面板和三个 Debian/systemd 容器，分别运行候选 Agent，使用独立数据库、凭据和 Docker 网络 `fxt-gost-audit`，未替换宿主机或原有环境的 Agent。

## 云端实测结果

数据端点先返回目标端口标识，再回传随机数据；测试同时校验目标路由和内容完整性，不仅检查端口能否建立连接。

| 场景 | 验证内容 | 结果 |
| --- | --- | --- |
| TCP、TLS、WSS、MTCP、MTLS、MWSS | 同一隧道多条规则，TCP/UDP 数据往返；各隧道出口只有一个监听器 | 通过 |
| 单个 NAT 可用端口 | 出口允许范围缩为一个端口，继续新增规则；防火墙只放行固定隧道承载端口 | 通过 |
| 有业务连接时新增规则 | 原 TCP 连接持续传输；出口配置文件摘要及运行时 PID 不变 | 通过 |
| 三主机多跳 TLS | 两条规则的 TCP/UDP 数据均经过多跳路径 | 通过 |
| WSS 双出口 | 两条规则反复 TCP/UDP 转发，各出口只有一个固定监听器；两边业务日志各检出 48 条匹配记录 | 通过 |
| TLS 双入口组 | 两台入口各自运行两条 TCP/UDP 规则，共用一个出口监听器 `23130` | 通过 |
| 转发组子规则 | 两条模板生成的子规则出口字段都为固定端口 `23100`，TCP/UDP 正常 | 通过 |
| 修改、停用、启用、删除 | 目标更新有效，停用及删除后业务端口不可用，其他规则最终恢复；出口配置及 PID 不变 | 通过 |
| 旧端口迁移 | 模拟旧随机字段及真实旧监听器 `23990`，协调后字段改为 `23100`，旧监听移除且业务恢复 | 通过 |
| 连续快速修改 | 连续修改同一规则 11 次，TCP/UDP 最终连接到最后指定的目标；实际运行规则状态恢复 | 通过 |
| 重启恢复 | 分别重启出口运行时、面板、入口 Agent，最终重新校验 23 条转发路径 | 通过 |
| Relay 认证 | 独立客户端分别不带凭据、携带错误凭据，均无法到达目标服务；合法业务保持可用 | 通过 |

结束前核对 24 条已启用的实际运行规则（不含模板）全部为运行中，没有待恢复规则；连接数限制规则单独验证。完成取证后已停止本次四个隔离容器，保留测试目录与容器用于复现。

### 流量统计

GOST 共享出口无法按公网端口区分业务规则，因此改为采信入口业务监听器的原生应用字节统计。出口和中继不再向单条规则重复记账。测试在采集基线建立、前序流量上报完成后开始，以面板数据库计数增量核对运行时计数。

| 场景 | 入口原生计数增量（入/出） | 面板累计增量（入/出） |
| --- | --- | --- |
| TCP 发送 4 MiB 随机数据并回传 | `4194304 / 4194308` 字节 | `4194304 / 4194308` 字节 |
| UDP 发送 20 个数据报并回传 | `20560 / 20640` 字节 | `20560 / 20640` 字节 |

TCP 返回方向多出的 4 字节为测试端点的目标标识；UDP 每个响应多 4 字节，共增加 80 字节。面板仅记录入口主机的业务计数，未将出口再记一次。此口径统计应用数据，不等于含 IP/TCP 包头和隧道封装的网卡流量。

### 限速与连接限制

- 同一隧道下两条规则分别配置 4 Mbps，并发各传输 4 MiB：实测为 **4.541 Mbps、4.504 Mbps**，墙钟约 7.46 秒，未因共用出口而合并成一个 4 Mbps 上限。短时突发会影响平均值，此测试用于验证逐规则限速仍生效。
- 建立三条 TCP 连接时，业务入口原生 `currentConns` 从 0 增至 3。
- 普通测试用户连接数上限设为 2：前两条连接正常，第三条被拒绝；释放后可重新连接。

## 实测中修正的问题

- 原有 GOST 统计按出口采信，改为共享监听后会漏记或无法正确归属。现在采信入口原生统计，跳过共享出口/中继的逐规则采集。
- 快速变更时，Agent 已采用本地配置但面板仍等待运行确认。现在对未确认的规则请求已有配置的状态回执，避免长期显示未运行。
- systemd 已报告运行、GOST 私有 API 尚未绑定时，紧接着的配置可能失败。现在对此启动窗口做短暂、有界重试。
- 旧规则随机出口字段、多出口映射及分组子规则统一协调到隧道端点，端口占用查询不再把 GOST 规则字段当成独立监听器。

## 更新注意事项与验证边界

面板和参与节点的 Agent 应配套更新。首次从旧逐规则监听器迁移时，会替换出口监听器；建议安排低峰维护窗口。后续新增规则已验证不修改出口运行时，也不打断测试中的既有 TCP 连接。修改或删除已有规则仍可能触发入口共享运行时重载，不能保证此类操作中的所有入口长连接连续。

上述结果来自单台云服务器内的多个隔离 Linux 节点，覆盖真实 Agent、GOST、数据库、内核防火墙和数据转发。它不能代替跨运营商公网、不同 MTU、IPv6、所有发行版或长时间高并发环境验证，也不构成生产环境零故障保证。
