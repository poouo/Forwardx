# 流媒体检测上报修复与云端验证

## 测试范围

2026-11-18，在用户提供的 Debian 13 云服务器上创建独立 Docker 面板和 Agent 容器，使用独立数据库和凭据。原有面板、Agent 和转发规则未替换。测试面板只绑定宿主机回环地址。

- 问题版本：面板 v2.3.302 正式镜像、Agent 2.2.214 正式二进制。
- 修复验证：只替换独立测试面板的服务端构建，Agent 二进制保持一致。
- 通过真实注册、心跳下发、Agent 外部 HTTP/DNS 请求和加密 `/api/sync` 上报完成验证；面板状态通过认证后的 tRPC 接口读取。

## 根因与复现

面板加密通道白名单遗漏 `/api/agent/stream-unlock-progress` 和 `/api/agent/stream-unlock-result`。Agent 实际将这些请求封装后发往 `/api/sync`，面板因此拒绝路由并返回 HTTP 400 `Invalid encrypted request`。

正式版本在云端复现：Agent 收到并完成任务，但所有进度和最终结果均上报失败。观察 25 秒内面板始终为 `running`，平台和 DNS 结果均为 0。该状态最终只能等待任务的 180 秒超时。

修复将这两个具体路径加入白名单，不放开其他路由。

## 修复后的真实结果

| 测试 | Agent 执行耗时 | 平台结果 | DNS 结果 | 最终任务状态 |
| --- | ---: | ---: | ---: | --- |
| IPv4 | 1.673 秒 | 12 | 7 | success |
| IPv4 + IPv6 | 1.256 秒 | 24 | 14 | success |

耗时取 Agent 上报的 `finishedAt - startedAt`，不包含用户点击后心跳调度与前端轮询等待。两轮均在 2 秒轮询后的下一次读取取得完整结果；首轮初次读取已收到部分平台和 DNS 结果。

IPv4 实际返回：8 项入口可访问，AbemaTV 返回 403，巴哈姆特未取得有效地区信息，ChatGPT 和 Grok 返回 403、无法确认地区开放状态。以上为该测试出口当时的响应，不代表其他机器的检测结果。

测试容器没有 IPv6 出口，双栈任务中的 12 项 IPv6 请求返回网络或地址解析失败，任务仍能正常结束。本次没有验证可用 IPv6 出口下各平台的解锁情况。

## 结果解释与限制

本轮证明任务下发、逐项上报和完成状态已恢复，不能将任务 `success` 理解为全部平台解锁。

当前部分探针只访问公开页面或登录入口，返回 200 只能作为入口可访问的依据，不能保证账号可登录、订阅可用或非自制内容可播放。403 也可能来自反爬，不应直接等同于地区未开放。本次没有取得有效的平台地区字段，也没有验证真实智能 DNS 解锁环境；地区和 DNS 解锁准确性不在本次通过结论中。

## 回归验证

- 新增使用真实 Express Agent 路由、临时 SQLite、注册凭据和加密 `/api/sync` 的集成测试。
- 覆盖逐项结果增长、IPv4/IPv6 结果同时保留、完成状态、迟到进度拒绝，以及白名单外路径继续拒绝。
- 将测试加入 `test:server`，确保常规 CI 会执行。
- TypeScript 检查与服务端构建通过。

原始状态采样与 Agent 上报失败日志保存在云服务器本次隔离测试目录中，未写入访问凭据到本报告。
