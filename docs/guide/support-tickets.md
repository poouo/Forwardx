# 工单支持

## 开启入口

工单系统默认关闭。先在「系统设置 → 左侧导航栏菜单展示设置」开启「工单支持」，再进入工单页，在右上角「设置」弹窗中开启「启用工单功能」，修改后立即保存。业务功能开关与菜单开关相互独立；菜单关闭时管理员和普通用户均不显示入口，管理员也可直接访问 `/tickets` 调整设置。

「系统设置 → 面板设置 → 左侧导航栏菜单展示设置 → 工单支持」仅控制普通用户侧菜单显示，与工单业务开关独立。首次升级继承原菜单开关的启用状态，此后隐藏菜单不会停用工单接口。

关闭「启用工单功能」会停用工单提交、查询和处理，不删除历史数据；重新开启后可继续查看和处理。无需更新 Agent。

同一弹窗提供「工单通知总开关」，默认开启。关闭后停止工单的 Telegram/Discord 推送，不影响其他通知、工单操作或用户个人通知偏好。通知渠道和机器人配置仍在系统设置中管理，个人绑定与接收偏好在个人资料中管理。

## 提交与回复

- 填写标题、分类、优先级和问题描述，支持技术、账务、账户及其他问题。
- 关联服务可以留空；可选择自己的订阅、规则、获授权的端口转发、隧道、转发组或可使用的按量计费服务。隐藏的中转/出口主机不会因为拓扑关系自动出现在列表中。
- 按量计费服务沿用原有授权策略：无须授权的服务可选，需要授权的服务仅在授权后可选。
- 服务删除或权限撤销不删除工单，历史关联名称仍保留，不会阻止服务删除。
- 附件支持 PNG/JPEG/WebP、PDF 和 UTF-8 TXT/LOG，每次最多 3 个、每个 2 MB，每个工单累计最多 20 MB，同一账号 24 小时内累计最多 50 MB。文件保存在数据库中，下载需登录并通过工单权限校验；不提供公开附件地址。
- 请勿上传密码、Agent Token、证书私钥等敏感数据。内容按纯文本展示，不执行 HTML 或脚本。

普通用户只可查看和操作自己的工单。未完成工单最多 10 个，滚动 24 小时内最多新建 20 个；回复间隔至少 3 秒、每小时最多 100 条。重复点击或并发操作产生版本冲突时，请刷新后重试，未发送的回复不会被自动清空。

## 处理流程

状态包括「待处理、处理中、待用户回复、已解决、已关闭」。管理员公开回复默认改为「待用户回复」，也可选择其他状态；用户回复后回到「待处理」。双方均可关闭或重新打开工单，关闭后须先重新打开才能发送公开回复。

管理员可以指派处理人、调整优先级和分类、批量解决/关闭工单，按编号、标题、服务、用户、状态、优先级、分类、处理人或未读状态筛选。支持共享快捷回复和仅管理员可见的内部备注；内部备注及其附件不会发给用户，也不改变公开状态或用户未读计数。

用户可对本人已解决/关闭的工单提交一次 1–5 分评价及文字反馈；重新打开后清除旧评价，下一次结束可重新评价。已关闭工单可由管理员二次确认后永久删除，连同回复、内部备注和附件一起移除。

## 提醒与数据保留

侧边栏显示未读工单数量，工单页定时刷新并在查看记录后标记已读。新工单和用户回复通知已绑定且启用当前 Telegram/Discord 渠道的管理员；管理员公开回复或公开状态更新通知提交用户。内部备注不通知用户，通知失败不影响工单保存。当前不发送工单邮件，不接收邮件或机器人消息作为工单回复。

SQLite、MySQL 和 PostgreSQL 启动时自动创建工单表。面板备份、数据迁移和数据库切换均包含工单、附件、已读状态和快捷回复；附件使用 Base64 存储，会增加数据库与备份体积。删除服务或账号不自动清理工单历史，管理员可按自身数据保留要求删除已关闭工单。
