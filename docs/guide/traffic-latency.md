# 流量和延迟图表

ForwardX 面板提供多维度的流量统计与延迟监控，帮助你判断转发是否正常运行、网络质量是否稳定，以及定位故障发生在链路的哪一段。

---

## 流量统计

### 统计维度

| 维度 | 说明 |
|---|---|
| 规则流量 | 单条转发规则的入站/出站流量 |
| 主机流量 | 某台 Agent 主机上所有规则的汇总流量 |
| 近 24 小时流量 | 按小时粒度展示最近 24 小时的流量趋势 |
| 累计流量 | 规则或主机自创建以来的历史总流量 |
| 用户流量 | 在用户权限模块下，每个子用户的独立流量统计，可用于套餐计费和额度管理 |

### 实时流量与累计流量的区别

- **实时流量**：体现当前时间段的吞吐速率，用于判断连接是否活跃、带宽是否充足。
- **累计流量**：反映历史总用量，是套餐额度扣减的依据。当用户到达流量上限时，面板会根据套餐配置限速或断开连接。

### 流量不增长的排查步骤

如果某条规则的流量长时间为零或停止增长，按以下顺序检查：

1. **确认是否有真实访问** — 在客户端发起连接，观察流量是否立即变化。
2. **确认转发方式支持统计** — GOST、FXP V1/V2、Nginx Stream 均支持流量统计；部分插件模式可能不上报数据。
3. **检查 iptables / nftables 规则** — Agent 依赖内核转发规则，规则丢失会导致流量不经过统计点。
4. **确认入口端口正确** — 面板显示的监听端口与客户端连接端口一致。
5. **确认目标地址和目标端口正确** — 转发目标不可达时连接会被拒绝，同样不产生流量计数。

## 延迟图表

### 延迟类型说明

ForwardX 展示两类延迟数据：

- **服务延迟**：从客户端建立连接到收到首字节的端到端响应时间，反映用户实际体验。
- **链路自测延迟**：面板/Agent 主动向目标发送探测包并测量往返时间（RTT），不依赖真实用户流量，可在规则空闲时持续监控。

### 如何看延迟趋势

- 延迟趋势图按时间顺序展示历史延迟变化。
- 短暂尖刺（单点高延迟）通常是网络抖动，不影响整体服务质量。
- 持续升高或长时间保持高位，说明链路存在拥塞或目标服务响应变慢。

**削峰 / 平滑显示**：如果图表因个别尖刺影响可读性，可在图表选项中开启削峰或移动平均平滑。该功能仅影响页面展示，不修改已入库的原始数据。

## 链路图与多跳延迟

### 链路拓扑

在使用转发链（Port Chain）或多级中转时，ForwardX 会将整条链路拆解为各段，并在链路图中展示：

```
客户端 → 入口节点 → 中转节点 1 → 中转节点 2 → 出口节点 → 目标服务
```

每一段都有独立的延迟和连通性指示。

### 如何看多跳延迟

- **不要只看总延迟**：入口到出口的总延迟是各段之和，单凭总延迟无法定位问题在哪一段。
- **重点看各段延迟**：找到延迟明显高于其他段的位置，该段所在节点或线路通常是瓶颈。
- **关注失败位置**：某段显示连接失败或超时，说明该段路径不通，需要检查对应节点的 Agent 状态和防火墙配置。

## 链路自测

### 自测原理

链路自测由 Agent 主动发起，向链路下一跳或最终目标发送探测，并将结果上报给面板。探测结果包括：

- 往返延迟（RTT）
- 丢包率
- 探测时间戳

### 读取自测结果

| 指标 | 参考值 | 说明 |
|---|---|---|
| RTT | < 50 ms（国内）/ < 150 ms（国际） | 超出范围说明该段网络质量较差 |
| 丢包率 | 0% | 任何丢包都值得关注，持续丢包影响 TCP 吞吐和 UDP 稳定性 |
| 探测失败 | — | 表示探测超时或目标不可达，需检查路由和防火墙 |

### 自测与实际用户延迟的差异

自测使用的是 ICMP 或轻量 TCP 探测，与真实业务流量的路径可能略有差异。如果自测延迟正常但用户反映延迟高，建议同时检查目标服务本身的响应时间。

## 常见问题

**流量统计和用户套餐额度是同一套数据吗？**

是的。面板流量统计与套餐额度共用同一套计量数据，规则产生的流量会实时累加到对应用户的额度消耗中。

**削峰功能会影响计费吗？**

不会。削峰和平滑只影响图表渲染，不影响入库数据和额度计算。

**Agent 离线后，自测延迟图表会显示什么？**

Agent 离线期间停止上报探测数据，图表对应时间段会显示为空白或断线，不会显示错误的延迟值。
