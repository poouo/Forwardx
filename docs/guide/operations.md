# 运维看板

[English](./operations.en.md)

管理员在「管理 → 运维看板」查看当天或最近 30 天的运行情况。

顶部可选择自动刷新档位：5s、10s、30s 或不刷新，默认 30s，并在当前浏览器按账户记住选择。流量、来源 IP、账务及已打开的详情使用同一档位；离开看板或切至后台标签页时暂停，返回后恢复。选择「不刷新」仍可手动刷新或修改筛选条件查询。

## 快速查看

1. 先选择北京时间日期范围和用户。「管理员」只统计当前管理员账户，要查看全站应选择所有用户。
2. 在顶部选择刷新档位；查看某一时刻的结果时可选「不刷新」，需要时手动刷新。
3. 查看流量趋势和资源排行；核对财务时切换到所需支付币种，分别阅读支付构成、余额消费构成及新建订单状态。
4. 环形图为空时表示当前筛选没有对应数据，不表示请求失败；请求失败时应检查页面提示和接口。订单异常到 [账单与兑换](./billing.md) 查看原始记录，不只根据汇总图判断。

![运维看板的日期、用户筛选与自动刷新档位](./images/operations-filters.png)

*本地开发演示：筛选为当前管理员和当天，自动刷新为 30s。*

## 流量与历史

- 按北京时间选择单天或日期范围，查看入向、出向流量与每日趋势。
- 默认选择「管理员」，查看当前管理员账户的统计，可切换所有用户或指定用户；趋势、排行、来源地图与 IP 详情同步筛选，主机状态和事件只展示所选用户规则关联的资源。
- 用户、主机、规则和链路资源分别提供流量排行。
- 多入口成员合并到逻辑规则；沿用正式流量统计的入口/出口归属，不重复累计中转节点。
- 展示实际规则流量，不使用计费倍率，也不等同于主机网卡总流量。
- 同时查看已观测到的主机离线时段与转发组事件。当前在线数不是历史在线数。

每日汇总保存在当前数据库，最多保留最近 30 个北京时间自然日。数据从升级后开始积累，不会补算升级前的记录。删除规则后已保存的汇总仍保留到正常过期。

完整数据备份会包含来源 IP 历史，请妥善保管；仅迁移核心配置时不会携带这些运维历史。

## 账务汇总

看板的账务区沿用相同的日期和用户筛选，默认「管理员」（当前管理员账户），可切换所有用户或指定用户。仅管理员可见。

- 在线实收：成功支付的正式充值和套餐订单，按币种分别汇总；不混算、不折算币种，测试、待支付、取消和失败订单不计入。
- 实收按支付时间归属日期；旧订单缺少支付时间时使用创建时间。新建订单状态按创建时间统计，因此与同期成功支付笔数可能不同。
- 余额消费单列套餐购买、附加流量和流量计费。充值订单与对应余额入账是同一笔资金的不同记录，不相加为收入；流量计费仅统计余额扣款，不再重复累计计费明细。
- 支付构成、余额消费构成和新建订单状态使用环形图展示金额或数量及占比；多币种支付可切换币种，空数据展示中性圆环。图表复用现有汇总数据，无动画、不增加请求，跟随日期、用户和自动刷新设置更新。
- 管理员充值、兑换入账及余额调整分别展示，不视作线上收款。余额流水使用现有人民币账本口径。
- 新增套餐记录按订阅创建时间计数，不代表购买或续费次数；当前生效套餐显示实时状态，不是历史快照。
- 支付和余额原始流水按事件时间倒序，每页 10 条，保留各自来源及状态，不直接合计；可前往完整账单继续处理。

直接查询已有账务数据，配合时间及用户索引和短期缓存，不另建重复财务账本，也不会随运维历史的 30 天清理删除账务记录。

## 来源 IP 与中国地图

在看板开启「采集来源 IP」，确认隐私提示。默认关闭，仅管理员可查看；关闭不影响转发，历史仍会按 30 天期限保留。

需要升级 Agent。设置通过流量上报响应同步，开启或关闭可能需要一至两个上报周期。旧 Agent 不会提供来源记录。

地图以蓝、青、绿、黄、红分档表示来源 IP 数。悬停显示入向/出向流量和流量前 5 个 IP；点击固定详情，查看关联规则数、主机数及城市/运营商（本地库有记录时）。角落展示境外来源及未定位数量。IP 列表每页 10 条，默认流量从高到低，也可按规则数或最近访问排序。支持搜索、翻页，点击 IP 可查看关联规则、主机、规则所属用户及采样流量。地图与总量汇总筛选范围内的全部记录，不只统计当前页。

注意这些统计的边界：

- 基于入口可见的连接跟踪快照，记录的是观测到的连接来源，不代表成功登录或完成协议握手的终端用户。
- 采样会遗漏在两次采集之间已经结束的短连接，流量是可观测的字节增量，不是完整会话流量或计费用量。首次采样、Agent 重启与计数器重置会建立新基线，不追溯旧流量。
- NAT、CDN、前置代理后的 IP 可能是网关/代理 IP；不会根据不受信任的 PROXY 头猜测真实来源。
- 支持具备本地规则状态和连接跟踪记录的普通转发入口；隧道出口和中转节点不纳入来源统计。ForwardX 原生隧道端点目前不提供独立的来源采集。
- 内核需要提供 `/proc/net/nf_conntrack` / `/proc/net/ip_conntrack`，或系统已安装 `conntrack` 命令并允许读取。采集器不会自动安装依赖或修改内核、防火墙配置。
- 缺少内核字节计数时仍可记录 IP，但流量显示「不可用」，部分缺失标记 `*`，不会当作真实的零流量。
- 每台主机每天最多保存 5000 个 IP/规则组合；每次最多上报 1000 项、跟踪 20000 条连接。达到上限、依赖缺失或状态过期都会在看板显示。
- 字节增量按采样时刻归入北京时间日期，跨日采样间隔不拆分。网络重试保留原采样日期，并使用流量报告的防重机制。

## IP 定位与隐私

来源 IP 使用随面板内置的 **ip2region IPv4 / IPv6 离线库**，国内省份与境外国家均可本地定位，不消耗第三方接口额度，也不会发送来源 IP。内网、保留地址和库中未知地址不推测位置；已有有效定位缓存仍可复用。主机等常规定位继续使用原有接口逻辑，不受影响。

查看看板时每次最多补全 256 个待定位 IP；点击「补全本地定位」每次最多处理 512 个，可逐步补全大量历史来源。结果单独缓存在当前数据库，最长 30 天；首次使用相应 IP 协议时按需加载本地库。资产压缩约 12 MiB，两种协议全部载入时约 46 MiB 数据内存，不会为每个请求重新载入。

地图轮廓和 IP 库均随源码、本地安装包及 Docker 镜像分发，无运行时下载。库丢失或损坏时记录告警，未定位地址继续显示未知，不自动改用外部 API。更新面板时携带新的库版本；结果只是网络地址段归属，不代表终端用户精确位置。请在开启采集前确认符合自己的隐私政策。

## 采集异常排查

在入口机器上检查（输出可能包含客户端 IP，不要未经脱敏公开）：

```bash
command -v conntrack
conntrack -L -o extended | head -n 5
sysctl net.netfilter.nf_conntrack_acct
```

Agent 安装和脚本升级会检查并尝试安装 `conntrack`，加载连接跟踪模块，开启 `net.netfilter.nf_conntrack_acct=1` 并读回验证。启动配置保存在 `/etc/sysctl.d/99-forwardx-source-accounting.conf` 和 `/etc/modules-load.d/forwardx-source-accounting.conf`，不覆盖其他内核配置。依赖安装、内核权限或持久化失败会明确告警，但不阻断 Agent 安装和正常转发。仅替换 Agent 二进制不会执行这些脚本检查；旧部署可重新运行当前 Agent 升级脚本补齐。

Debian/Ubuntu 也可手动执行 `apt-get install conntrack` 和 `sysctl -w net.netfilter.nf_conntrack_acct=1`。开启后通常只有新建立的连接才包含字节计数，不断开现有连接，不补算旧历史；已有未知样本在所选日期内仍标记为不完整。运行时采集只读取连接跟踪，不反复修改内核参数。受限容器、内核不支持或其他配置覆盖该选项时，需要主机管理员处理。
