# AI 助手

AI 助手通过已选择的 Telegram / Discord 机器人提供自然语言查询与受控管理，需要先完成 [通知渠道配置与账号绑定](./notifications.md)。

## 配置 AI 助手

AI 助手用于所选机器人渠道的自然语言查询和管理指令解析。进入：

```text
系统设置 -> 通知渠道 -> AI 助手模型
```

按顺序配置：

1. 选择供应商：DeepSeek、SiliconFlow 或自定义 OpenAI 兼容接口。
2. 填写 API Key。
3. 检查 Base URL。DeepSeek 默认是 `https://api.deepseek.com`，SiliconFlow 默认是 `https://api.siliconflow.cn/v1`。
4. 选择或填写模型名称。
5. 按需调整最大输出 Tokens 和温度。
6. 打开"启用 AI 助手"并保存。

启用后，可以在机器人中发送：

```text
/ask 我的流量用了多少
/ask 查看我的转发规则
/ask 哪条规则延迟最高
/ask 帮我关闭第 12 条规则
```

AI 助手内置 `ForwardX Core Skill`，用于理解主机、规则、隧道、转发组、用户和计费相关术语。模型只负责识别意图，不会直接读取面板数据库，也不会生成命令在服务器上执行。

AI 操作使用“目标理解 → 按需读取上下文 → 结构化计划 → 业务校验 → 用户确认 → 执行反馈”。简单请求可以直接生成计划，复杂请求最多进行三轮内部规划。模型不能直接执行脚本、SQL、网页操作或任意 API；不支持的配置会明确说明，不会自动转换成其他修改。

规划过程中，面板可能向所配置的 AI 服务发送当前用户有权限查看的最少资源元数据，例如规则 ID、名称、端口、目标地址、状态以及相关账户额度。不会发送密码、Agent Token、机器人 Token、隧道密钥或完整数据库记录。请选择可信的 AI 服务。

## 继续未完成的 AI 操作

例如发送“给用户 2 充值并续费”，机器人会逐项询问金额、期限，并在每一步执行前要求点击确认。完成充值后，才会继续续期步骤；已完成的步骤不会因重启重新执行。

- 发送 **继续**（或 `/ask 继续`）恢复当前待办；输入已知字段的修正信息可以重新生成确认卡片。
- 发送 **取消** 结束剩余操作，但不会撤销已经完成的步骤。
- 待补充项、参数及剩余步骤保存在面板数据库中，不再一分钟后丢失；返回菜单不会清除待办。
- 确认按钮仍有 10 分钟有效期。过期只会使按钮失效，发送“继续”会重新校验并生成新确认，不会丢失参数或自动执行。
- TG/Discord、账号与聊天分别隔离。一个请求最多六个顺序写步骤，每一步都要确认；只读查询不需要确认。
- 如执行过程中断，面板无法确定是否已生效，会保留待办并要求核实实际结果，不自动重复充值、续期或创建。完成/取消的操作记录保留 30 天；未完成及结果不确定的待办不按此期限清理。
- 常规合并迁移会重映射资源 ID，因此不会导入旧 AI 待办及确认授权；保留原 ID 的无缝迁移可保留待办。恢复后仍会检查当前权限。

自然语言管理已覆盖以下常用区域（普通用户仍受自身权限限制，系统设置、主机配置及其他用户管理仅限管理员）：

| 区域 | 支持内容 | 示例 |
| --- | --- | --- |
| 规则 | 查询状态、流量/连接/延迟排行；新增、修改、启停、删除；目标、端口、工具、PROXY、协议限制和故障转移配置 | “哪个规则流量最多”“把规则12的目标改成 example.com:443” |
| 到期 | 账户、主机、订阅的到期筛选和排序；可指定天数及是否包含已到期 | “哪些主机3天内到期”“哪些规则所属账户7天内到期” |
| 系统设置 | 注册、两步验证、多设备登录、插件、公开首页/监控、用户网络测试、协议可用性、侧栏菜单、邮件/DDNS、通知提醒、AI用户管理/自动撤回、商店及兑换/折扣功能；提醒阈值和站点名称等 | “关闭插件，开启多设备登录”“关闭邮件到期提醒” |
| 主机 | 端口范围、流量额度与统计方式、达量剔除、流量重置、续费提醒、账单周期、到期处理、DDNS及协议限制；指标和流量查询 | “把主机3续费提醒改为提前3天” |
| 隧道 | 新增和修改；启停、入口/出口、协议、监听端口、限速、倍率、PROXY等；证书内容仍在网页配置 | “关闭隧道2”“把隧道2限速改成100Mbps” |
| 转发/入口/出口组、链 | 新增、修改配置或成员、启停、同步、事件查询 | “关闭转发组2”“将转发链3的工具改成gost” |
| 用户 | 原有充值、续期、启停账号及转发；额度/期限/限速调整、手动主机/隧道/组授权的增减或明确全量替换 | “给用户2新增主机3的使用权限” |
| 套餐与计费 | 套餐查询、新增、修改、上架/下架；订阅查询、分配、延长、取消；账单概览及资源按量计费配置 | “查看我的订阅”“把套餐2下架，保持启用” |
| 公告 | 查询、发布普通/弹窗公告、删除，可明确选择是否推送 | “发布普通公告：今晚维护，不推送” |

新增规则可以直接指定已有端口转发组/转发链或隧道；不支持仅给主机ID而绕过端口转发链创建。缺少端口、目标、资源或其他必需参数会追问；源端口 `0` 仅表示用户明确要求随机分配。新建资源使用的网页默认值会列在确认预览中。

“我的订阅”“我的规则所属账户到期”等请求按本人筛选，即使发起人是管理员也不会默认扩大到所有用户；明确查询全部时仍只返回当前账号有权查看的数据。

增减授权在服务端锁内处理，保留其余手动授权；全量替换会明确提示清单含义，套餐授权不受影响。设置、组和套餐使用局部修改，不把未提及字段重置为默认值；确认前配置已经变化时，本次拒绝执行，可发送“继续”重新预览。

密码、管理员角色、API Key/Token、私钥、数据库连接与切换、面板迁移/升级、支付执行、任意脚本及插件任意参数，不开放给自然语言写工具。机器人/通知渠道及AI本身的启停也保留在网页，避免对话中切断确认和反馈渠道。工具不支持的操作会明确说明；不能因AI理解了文字就绕过业务校验。

- 查询由面板本地读取数据，并根据当前用户权限过滤结果。
- 管理操作与网页端共用相同业务校验，仍会检查协议、端口、资源权限、套餐和计费状态。
- 所有写操作必须先查看预览，再点击"确认执行"。
- 缺少金额、续期时长、兑换码数量或折扣力度时，机器人会给出常用选项；也可以点击"自定义输入"或直接发送自定义内容。
- 单次模型请求（包含响应正文读取）约 12 秒超时，复杂请求最多三轮；连续异常时会短暂熔断。服务异常不会把新请求猜成写操作；已有待补充项仍可使用本地解析，原待办保持保存。
- 每个用户每分钟最多发起 20 次 AI 交互，达到限制后需要等待提示时间再试。
- 同一聊天中的消息按顺序处理，不同用户的聊天可以并行处理。

管理员可以查询更多面板信息，也可以通过 AI 辅助执行部分管理操作。涉及修改数据的操作会要求二次确认。

## 普通用户 AI 管理开关

"普通用户可用 AI 管理"只控制普通用户是否能通过 AI 对话执行管理操作。

- 开启：普通用户可以用 AI 管理自己的可见规则，例如新增、删除、启用或停用自己的规则。
- 关闭：普通用户不能用 AI 对话执行管理操作。
- 普通查询不受影响。
- 管理员不受影响。

普通用户无论是否开启，都只能操作自己的账号和自己有权限的资源。

## AI 消息自动撤回

打开"机器人信息自动撤回"后，AI 相关聊天内容会在设定时间后自动撤回。

可配置时间范围为 30 秒到 1200 秒。此功能只影响 AI 相关消息，不影响普通命令的必要提示。

## 对话创建规则与动态选项

例如发送：`帮我添加转发规则到目标10.10.10.10:22`。

机器人会保存目标，并动态展示当前账户有权使用的隧道、端口转发链和转发组；资源较多时可以翻页。选好链路后，点击随机分配入口端口或手动输入端口号，再选择 TCP、UDP 或两者。规则名称未指定时按目标地址生成，并在最终确认预览中展示。

点击这些选项只是在补齐参数，不会创建规则；最终点击 **确认执行** 才会调用实际业务接口。即使只有一条可用链路，也需要明确选择。待办在重启后仍保留，可发送“继续”恢复；旧按钮失效，资源或授权变化后会重新校验。已知设置开关需要补充状态时，也可以直接点击开/关按钮，再确认修改。Telegram 与 Discord 使用相同流程。

## 常见排查

未配置 API Key、模型列表加载失败时，检查供应商、Base URL、密钥和面板服务器到供应商的网络。普通用户不能写操作时，检查当前渠道账号绑定、AI 启用状态、普通用户管理开关及资源权限。模型理解成功不代表业务校验一定通过。

单条规则额度与期限的完整说明见 [转发规则](./rules.md#单条规则限额与有效期)。
