# 迁移到新面板

迁移与原地升级是不同操作。先备份两端数据库，确认模式和限制后再操作；旧数据不会因迁移自动删除。

## 无缝模式（默认选择）

无缝模式将管理和计费迁移到新面板，Agent/FXP 保持使用原来的面板 URL，由旧面板转交原始加密请求、SSE、流量报告和支付回调。迁移本身不下发停止、升级或重建转发进程的指令；管理 SSE 可重连，已有业务 TCP 连接不因迁移被主动关闭。这不等于保证主机故障或网络中断时连接也不会断开。

前提：两端面板版本和数据库类型一致；所有主机已使用当前 Agent 或更新版本；目标无业务数据（允许一个初始化管理员）；旧端已配置正确的公开地址。迁移填写的旧地址必须与 Agent 原有面板公开地址一致。新面板的初始化管理员会由旧端账号替代，新面板需要重新登录，不迁移浏览器 Cookie/JWT 密钥。新端数据库连接设置、面板 SSL 配置保留为新端原配置，不覆盖成旧域名的证书；文件路径型证书、外部文件/反代配置仍须提前在目标机器准备。

1. 先备份两端数据库，将新面板公开地址配置好；不要改 Agent URL 或重启转发进程。
2. 在旧面板生成迁移码，在新面板初始化向导或系统设置中启用“无缝迁移（旧地址转交）”，填写新旧地址和迁移码。
3. 旧面板管理员核对地址和模式后批准。旧面板暂停新操作、后台任务和计费写入，等待已进入的操作完成，再导出一致快照。转发数据面仍继续工作，Agent/支付回调短暂返回可重试的错误。
4. 新端事务导入并校验行数，保留原 ID、Token、端口、累计计费和运行状态。成功后旧端开始转交请求，新端仅接收报告、验证原在线主机及运行规则/隧道的本地可用状态，暂不下发配置变化。
5. 验证通过后新面板恢复正常管理。旧数据库保留、旧后台写入停用。

此模式只支持单实例面板，迁移期间两端数据库不能有其他面板实例或外部程序写入；不会自动协调共享同库的多副本部署。旧端仍处于冻结、尚未转交请求时，可以用原来仍有效的管理员会话取消冻结并恢复旧端。已经转交后禁止取消，须在新端继续验证，以免两端同时计费。

**必须持续保留旧面板接入地址及转交服务，不能停止或卸载旧面板。** 旧数据库不再用于管理或计费；所有操作在新面板进行。这是兼容当前在跑 Agent/FXP 的网关式迁移，不是彻底删除旧服务器的迁移，也不支持增量合并。如果要撤掉旧服务器，需要另外迁移旧域名/接入网关，并验证接入 URL 和认证不变。

迁移状态写入数据库配置目录旁的 `seamless-migration.json`（可用 `FORWARDX_SEAMLESS_MIGRATION_STATE_PATH` 指定路径），应与配置一起持久化；该文件含私密接管凭据，不要公开、删除或复制到无关部署。接管前导入失败会事务回滚，源冻结未转交时最多一小时后解除；接管请求发出后如遇网络错误，保留新端验证态，登录管理员点击“继续验证并接管”。不会自动让旧数据库恢复写入，以免重复计费。若接管前源冻结已到期，则旧快照不能继续接管，应备份并重新准备空目标重新迁移，不能强行使用过期快照。

此模式的验证确认数据和本地运行状态，不替代业务协议层端到端测试；建议迁移时保持一条实际业务长连接并检查转发进程 PID 未改变。

## 普通模式（关闭无缝开关）

迁移前先将新旧面板升级到支持安全迁移的同一版本，并确认旧面板中的在线 Agent 可以正常心跳。

1. 在旧面板的系统设置中生成迁移码。
2. 在新面板初始化向导或系统设置中填写旧面板地址、迁移码和新面板访问地址。
3. 回到旧面板，核对目标地址后批准迁移请求。
4. 等待新面板完成数据校验、公开地址验证、Agent 预切换和原运行规则恢复检查。
5. 页面显示迁移完成后，使用旧面板账号登录新面板检查业务。

普通模式会切换 Agent 的面板 URL，可能触发转发运行时重建，不保证已有连接不中断。只有新面板地址确实指向当前面板、原在线 Agent 已回连，并且迁移前运行的规则和隧道重新运行后，旧面板才会停止控制 Agent。接管提交前检查失败会取消预切换。

旧面板数据库和所有业务记录不会被自动删除。普通模式确认新面板稳定运行后可手动停止旧面板；无缝模式必须持续保留旧地址与转交服务。
