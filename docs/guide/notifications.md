# 通知与机器人

支持邮件（SMTP）和 Telegram / Discord 机器人。机器人渠道二选一，默认 Telegram；邮件可以与所选机器人同时启用。

## 选择通知渠道

进入「系统设置 → 通知渠道」，选择 Telegram 或 Discord，并保存通知渠道。只有所选渠道发送机器人通知与处理交互；切换不会删除另一渠道的配置和用户绑定。

管理员与用户分别绑定自己的账号。主机、规则、转发组上的单项通知开关仍需按需开启，不能只配置 Bot Token。

## 邮件通知（SMTP）

在「系统设置 → 邮箱设置」配置并启用邮件：

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 服务商提供的发送服务器域名 |
| 端口 | 通常为 465 或 587，以服务商要求为准 |
| 加密方式 | 隐式 TLS、STARTTLS 等，与服务器配置匹配 |
| 用户名、密码 | SMTP 凭据；支持应用密码的服务商优先使用应用密码 |
| 发件人地址 | 服务商允许该账号发送的邮箱地址 |

保存后发送测试邮件，检查收件地址、垃圾邮件箱和服务商发信限制。邮件配置保存在面板数据库，当前不支持用 SMTP_HOST / SMTP_PASS 等环境变量代替页面配置。

用户到期/流量提醒发送至用户账号邮箱；是否发送还取决于对应提醒开关。邮件验证、提醒与机器人是不同配置，不要将机器人绑定当成邮箱配置。

## Telegram

### 创建与启用

1. 在 Telegram 的 @BotFather 使用 /newbot 创建机器人。
2. 复制 Bot Token，在面板通知渠道选择 Telegram，填写并启用。
3. 管理员绑定自己的 Telegram，再测试通知。

也支持 TELEGRAM_BOT_TOKEN 环境变量；环境配置优先，页面会显示来源。Docker 需要实际传入容器，不是仅追加 .env 即生效，见 [环境变量](./env-vars.md)。

机器人使用长轮询，面板服务器需访问 api.telegram.org，不需要设置 Telegram webhook。

### 用户绑定

在个人中心或账号菜单打开 Telegram 绑定，生成一次性绑定码后跳转机器人并点击 Start，也可在私聊发送：

~~~text
/bind 绑定码
~~~

## Discord

### 创建与启用

1. 在 [Discord Developer Portal](https://discord.com/developers/applications) 创建应用与 Bot，取得 Bot Token。不要填写用户 Token 或 Webhook URL。
2. 在面板选择 Discord，填写 Token、启用并保存；也支持 DISCORD_BOT_TOKEN 环境变量，环境配置优先。
3. 使用面板邀请链接将机器人加入与用户共同的服务器。OAuth scopes 为 bot 和 applications.commands，无需 Administrator 权限或 MESSAGE CONTENT 等特权 intents。
4. 用户允许来自服务器成员的私信，在个人中心或账号菜单生成绑定码，在机器人私聊发送 /bind DC-...。绑定码 5 分钟有效、只能使用一次。
5. 管理员完成自身绑定后点击「测试发送」，再启用需要的提醒。

面板服务器需访问 discord.com 的 HTTPS API 与 gateway.discord.gg 的 WSS。无需公网交互回调或额外开放入站 Discord 端口。

### 与 Telegram 的差异

- 只在机器人私聊中处理账户命令和按钮，不向公共频道泄露账户信息。
- 不提供 Telegram 内嵌 WebApp；/login 与 /webapp 兼容别名生成 5 分钟有效、一次性的普通浏览器登录链接。
- 长消息拆分，按钮附于最后一条。自动撤回只能删除机器人自己的消息，不能删除用户私聊消息。
- 用户关闭私信、拉黑机器人或失去共同服务器时通知可能失败。
- 绑定、登录码及公告订阅分别保存，不把 Telegram ID 当作 Discord ID 使用。
- 私聊 Slash Commands 注册可能需要时间生效，也可直接发送文字指令。

## 查询和操作

两种渠道提供相近的账户查询、规则管理、兑换与管理员操作；仍受用户权限及配置开关限制。

| 命令 | 用途 |
| --- | --- |
| /menu、/usage | 菜单与账号用量 |
| /rules | 查看并管理有权限的规则 |
| /redeem | 兑换余额或套餐 |
| /login | 获取一次性网页登录链接 |
| /unbind | 解除当前渠道绑定 |
| /ask 问题 | AI 查询与受控操作，需配置模型 |
| /users、/reset、/renew | 管理员用户查询、流量重置和续期 |
| /updatepanel、/updateagent | 管理员更新操作，需要确认 |

机器人不能绕过管理员自定义规则的只读限制。管理员密码、Token、任意脚本等敏感操作不因接入 AI 而开放。

## 提醒

可按需配置主机上下线、流量不足、套餐到期、服务器续费、转发组切换、规则异常等通知。发送对象、渠道和触发条件由对应设置决定，不是每类事件都会同时发送邮件和机器人。

续费提前天数、流量阈值与主机账单周期在相关页面配置；测试消息成功不代表业务提醒开关已经启用。

## AI 助手

模型设置、自然语言查询、动态按钮创建规则及未完成操作恢复已整理到 [AI 助手](./ai-assistant.md)。写操作需要明确预览和确认，不由模型直接执行命令。

## 排障

- 无回复：检查所选渠道、启用状态、Token、服务器出站网络和绑定状态。
- 保存提醒提示先配置机器人：先配置并启用当前渠道，再打开对应提醒。
- Discord 通知失败：检查私信权限、共同服务器、机器人身份和 Gateway 连接。
- AI 不可用：检查模型密钥、Base URL、供应商网络与普通用户管理开关。
- 查看 [面板日志](./paths-logs.md)，按故障时间检查固定错误原因，不要公开 Bot Token。

Bot Token、SMTP 密码和 AI API Key 均属于敏感凭据，不应出现在公开截图、仓库或排障工单中。
