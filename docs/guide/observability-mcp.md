# 网络诊断、资源告警与 MCP

本页介绍新增的诊断、告警及外部 AI 查询功能。它们复用当前账户权限，不会因为使用 AI 而获得额外资源访问权。

## 网络测试

进入「网络测试」，按原有流程选择 Agent、测试类型及目标。

- Ping 结束后，已识别的输出会展示丢包率、平均/最大延迟及延迟标准差。
- Traceroute / MTR 展示逐跳结果，保留超时节点；原始输出仍可查看和复制。
- 中间路由器可能不回应 ICMP，单跳超时或 100% 丢包不能直接解释为业务丢包，应结合末跳、TCP 和实际业务判断。
- 无法识别的输出只展示原文，不推算数值；执行中不展示上一轮摘要。

页面下方「网络配置体检 → 开始检查」检查所选主机的 Agent 绑定、近期通讯和资源采样。复制排查报告后可发给管理员；报告不含认证密钥，但资源名称可能包含个人信息，请先检查再转发。

AI / MCP 的 `network.diagnose` 还可指定 `ruleId`，检查规则开关、运行上报、授权、有效期、所属账户和目标配置。`hostId` / `ruleId` 必须二选一。规则存在不代表用户可以查看所有内部节点详情。

配置体检不发起网络探测，不能证明目标业务连接成功，也不替代流量额度、目标服务和防火墙的进一步排查。

## 运维看板

管理员在「运维看板」底部查看「状态与告警记录」。此处只展示全局状态，不随流量区域的用户和日期筛选变化；配置统一在「主机管理 → 服务管理」维护。

- 展示最多 10 台有采样主机的近期 CPU、内存、磁盘使用率，优先展示新鲜且高负载的数据。
- 超过 120 秒没有新采样时标记过期，不用旧数据冒充当前状态。
- 基础安全检查包括管理员 2FA 覆盖、公开地址 HTTPS 配置和开放注册状态；不扫描进程、不进行入侵检测，也不验证实际证书链。
- 展示最多 50 条当前告警及最近 30 天的分页事件记录。
- 国内健康检测页展示检测状态和最后采样时间；IP 更换记录单独分页展示近 30 天的请求结果和返回的新 IP，不展示商家密钥。
- HTTP 2xx 仅表示商家已接收请求，不代表 IP 已更换。结果不明确时，在国内健康检测页核对商家结果后解除保护，不会自动重发。

### 开启资源告警

进入「主机管理 → 服务管理 → 添加服务 → 资源告警」页签：

1. 填写服务名，在「告警项目」中选择 CPU、内存或磁盘，每条服务只负责一项；右侧「启用服务」可随时切换。
2. 设置该项目的阈值，默认 90%。需要监控其他项目时，另行添加服务，也可为同一项目设置不同范围、阈值或观察时长。
3. 设置连续超限时长，默认 300 秒。
4. 设置恢复观察时长，默认 60 秒。下降至阈值减 5 个百分点或更低，并持续达到恢复时长后，才记录恢复。
5. 在参数下方选择主机范围：「所有主机」「特定主机」或「排除主机」。特定/排除模式支持多选和移除；特定模式至少选择一台主机。
6. 主机范围右侧的「发送通知」仅通知已绑定 Telegram / Discord 等通知渠道的管理员；关闭后仍保留告警记录。
7. 点击弹窗底部「保存」，服务会出现在服务管理列表中，可独立编辑、启停和删除。状态及历史记录在运维看板查看。

每条服务的阈值应用于各自所选范围。「所有主机」自动包含以后新增的主机；「排除主机」监控除排除列表以外的主机，也包含以后新增的主机。「特定主机」仅监控所选主机。

旧版多项目告警配置会按 CPU、内存、磁盘拆成独立服务，保留原阈值、范围、启停和通知设置，阈值为 0 的项目不转换。编辑或启停仅重置对应服务的观察状态，不影响其他服务；删除服务仍保留历史事件。

每台主机最多每 30 秒处理一次资源样本。采样间隔超过 120 秒会重新计算待触发/待恢复的连续时长，不因断联而自动判定恢复。已触发的告警会保留并标记采样中断。

同一状态只在触发和恢复时记录事件、发送通知，不每次心跳重复通知。修改设置会重新开始观察，不补发虚构恢复事件。此功能不会杀进程、修改防火墙或重启机器；主机上下线通知仍由原有开关独立控制。

## AI 精确查询

在已配置的机器人中可以询问：

```text
/ask 当前有几个用户
/ask 普通用户有多少个
/ask 当前流量排行前三个
/ask 昨天主机流量前五个
/ask 最近7天规则流量前三个
/ask 我的规则流量前五个
```

数量和排行由数据库聚合计算，再限制返回条数，不从模型看到的部分列表猜总数。用户统计含匹配总数、普通用户数、管理员数、启用/停用和到期数量；这些状态有重叠，「启用」不代表「在线」。全站用户统计仅管理员可查。

未指定排行对象与时段的「当前流量排行前三个」，默认返回**今天的用户流量前 3 名**，按北京时间自然日及双向实际流量计算。「我的」即使由管理员询问，也只统计自己。

可显式选择用户、规则、主机或链路资源，以及入向/出向、今天/昨天/最近 7 天/最近 30 天/自定义日期。规则按逻辑规则合并，多入口不会显示成多个独立规则。普通用户仅可查询自己的流量。

排行使用当前仍保留的日汇总，返回统计日期、查询时间及现存历史起点。不含计费倍率，不等于账户累计额度用量，不会补造升级前或已清理的历史。未明确的问题仍由模型解析；无法确定时应进一步指定对象和日期。

## 外部 MCP 接口

这是仅供管理员使用、让外部 AI 客户端调用 ForwardX 的 MCP 服务，不是让面板自动连接任意外部 MCP 服务。无需启用面板内的 AI 模型；外部客户端使用自己的模型。普通用户原有机器人 AI 查询和受控管理能力不受此限制影响。

### 创建访问凭据

1. 使用管理员账户，在实际部署的 HTTPS 面板进入「系统设置 → 通知渠道」，找到 AI 配置下方的「外部 MCP 接口」。
2. 输入客户端名称，选择 7 / 30 / 90 天有效期，点击创建。
3. 令牌只展示一次，立即保存到客户端的安全配置中。每个账户最多 10 个有效令牌。
4. 不再使用时在同一页面撤销；令牌到期、撤销、账户禁用或管理员降为普通用户后无法访问。之前已创建的普通用户令牌同样无法访问。

服务器只保存令牌哈希，不提供找回明文。请勿把令牌放进 URL、工单、日志或公开仓库。

### 客户端配置

客户端需支持 **Streamable HTTP** 和自定义 Authorization 请求头，不是旧版 SSE `/sse` 接口。

```text
URL: https://panel.example.com/mcp
Transport: Streamable HTTP
Authorization: Bearer <你创建的令牌>
```

支持通用 `mcpServers` 配置的客户端可参考下例；各客户端字段可能不同，以其文档为准：

```json
{
  "mcpServers": {
    "forwardx": {
      "url": "https://panel.example.com/mcp",
      "headers": { "Authorization": "Bearer <令牌>" }
    }
  }
}
```

反向代理需放行 `/mcp` 的 POST 和 Authorization 请求头。纯浏览器跨站客户端目前不开放跨域调用；若请求携带 Origin，只允许与系统设置的面板公开地址同源。

### 能力和边界

- 只开放现有只读工具：精确用户统计/搜索、流量排行、可见规则/主机/隧道、仪表盘、订阅、网络配置体检等。
- 管理员另可查询资源告警、安全配置、账务及白名单内的系统设置，不返回密码、密钥或任意系统设置。
- 令牌管理和 MCP 请求均在服务端校验管理员身份，普通用户不能创建、列出、撤销令牌或调用接口。管理员令牌权限较大，谨慎交给第三方模型。即使不含密钥，业务数据、IP 和资源名称也可能敏感。
- 不提供任意 SQL、命令执行、任意 HTTP 代理或写操作。修改仍在面板或机器人确认流程中完成。
- 单次 JSON 请求上限 64 KiB；每 IP 每分钟最多 120 个请求，每账户每分钟最多 30 次工具查询，超限返回 429。
- `401` 检查 Bearer 请求头、有效期和账户状态；`403` 检查管理员身份、Origin 与公开地址；`405` 检查传输是否使用 POST；`413` 缩小请求；`429` 降低频率。

完整数据库备份可能包含令牌哈希及告警历史，仍需妥善保管；完整恢复后未过期令牌可能继续有效。核心配置合并迁移不迁移这些新增表，迁移后需重新创建令牌并重新观察告警。

## 中转建连失败切换

FXP 在已有多候选节点配置下，建连/认证或发送初始 hello 失败时，会关闭失败连接并尝试其他候选节点；同一次建立过程对每个候选最多尝试一次。修正了同端口不同 IP 时故障节点识别可能混淆的问题。

这是**业务数据发送前的建连失败切换**，不是连接建立后的断点续传。已传输业务数据的 TCP 连接不会跨中转盲目重放，避免重复提交或数据乱序；也没有新增并行中转组或序号/ACK/重组协议。

## 后续验证

- 已建立连接的跨中转恢复/重传协议尚未实现，需要另行设计与联调。
- 新增统计和告警数据库路径已做 SQLite 集成测试，仍需 MySQL / PostgreSQL 实库验证。
- 仍需 Linux 多节点断网、丢包与长时间负载验证，以及手机/桌面浏览器视觉验收。
- Windows 上部分现有 V3 会话测试在修改前也会失败，应单独跟踪，不视为本次新增测试通过。
