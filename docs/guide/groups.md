# 转发组、入口组与出口组

ForwardX 提供三类”组”资源，分别服务于不同场景：转发组用于业务入口的高可用故障转移，入口组和出口组用于复用主机集合、简化多规则配置。

---

## 转发组

### 概念

转发组让多台入口主机同时为同一个目标提供服务。任意时刻只有一台主机作为当前入口，其余成员作为备用。结合 DDNS，故障时系统自动将域名切换到下一台可用主机，实现业务连续性。

```
入口 A ──┐
入口 B ──┼──> 目标（业务端口 / 协议 / 目标地址）
入口 C ──┘
```

> 业务端口、协议和目标地址仍在转发规则中单独配置，转发组只管理入口主机集合及故障切换策略。

### 成员管理

- 成员列表中的顺序即优先级，排在最前的主机为首选入口。
- 拖动成员可调整优先级；保存后会立即刷新所有引用该组的资源。
- 主机型转发组使用主机成员，隧道型转发组使用隧道成员；多入口隧道场景请使用入口组。

### 故障转移与 DDNS

当前入口失效并持续达到组内配置的**故障窗口**时，系统切换到下一个可用成员，并同步更新 DDNS 解析记录。

记录类型可选 IPv4 / A、IPv6 / AAAA 或 A + AAAA。双栈模式会将两种记录一起切换到当前活动成员；成员仅有一种地址时，另一种旧记录会被清理，避免仍指向旧入口。

| 设置 | 行为 |
|------|------|
| 开启「恢复后切回」 | 高优先级成员恢复后自动切回 |
| 关闭「恢复后切回」 | 保持当前成员，直到它再次失效才继续切换 |

> 故障窗口时长在转发组配置页调整，默认值兼顾响应速度与抖动抑制。

## 入口组

入口组将多台入口主机保存为一个可复用资源，供普通端口转发、隧道或转发链直接引用，避免在每条规则中重复填写相同的主机列表。

- 可为入口组配置统一的 DDNS 域名，由系统自动维护解析记录。
- 支持 A + AAAA 双栈解析；各成员按实际 IPv4 / IPv6 地址参与，健康成员变化时同步两种记录。
- 也可关闭自动解析，改由自行维护 DNS 记录。
- 引用入口组后，系统按成员数量生成对应入口路径；成员或地址变更后，所有引用资源会同步刷新。

### 普通端口转发使用入口组

1. 保存入口组，选择需要同时提供服务的主机（最多 20 台）。入口组沿用已有域名字段；可以关闭自动解析自行管理 DNS。
2. 新建或编辑「端口转发」资源，将「入口类型」改为「入口组」，选择已保存的入口组和转发工具。
3. 在转发规则中选择该资源，填写统一的监听端口和目标地址即可。

所有已启用入口**同时监听相同端口并直连目标**，无需隧道或独立出口。不复制同一连接，也不在入口之间执行主备切换；客户端连接哪个入口，就由该入口转发。单主机模式保留原有行为。

卡片与列表沿用转发链的资源展示风格：成员区标明所引用入口组和入口主机，「入口」显示入口组域名（没有域名则显示组名）。成员区内只显示入口节点数量和「节点详情」按钮，点击后在独立弹窗查看，不撑高卡片或列表行；多个入口是并行关系，不表示多跳链路。

- 新建规则的端口需在所有已启用入口的允许范围交集中，并且在各节点均无冲突。
- 修改目标、协议、端口或启停规则会同步到所有入口。增删入口成员只调整对应节点，未变更且正常运行的规则保留运行状态。
- 后加入的节点若端口冲突或超出允许范围，其他节点继续运行；资源状态说明显示规则 ID、主机 ID 和原因，冲突约每 60 秒重试。Agent 离线/下发失败沿用现有心跳重试机制。
- 资源同时显示正常入口节点数和运行规则数。例如三台入口各有两条规则，监听 `4/6` 不等于正常节点 `2/3`：只有主机在线、未被流量策略排除、全部启用规则已运行且无同步错误，才算正常节点。这不是端到端业务连通性保证。
- 点击「节点详情」可在弹窗查看每台主机的状态、配置同步失败次数、最近原因及最早重试时间。Agent 执行失败另列连续失败次数；每节点最多展示三条代表性同步错误和三条执行错误。内容较多时仅弹窗内部滚动，关闭后返回原卡片。
- 配置同步冲突最早约 60 秒后重试；新版 Agent 执行失败使用约 30 秒重试冷却。显示的是**最早可重试时间**，实际执行还取决于调度、心跳与 Agent 连接，不是完成时间承诺。旧版 Agent 不上报具体次数和时间，仍可使用原有重试机制。
- 保存启用的端口资源或新增规则前，会根据近期 Agent 上报检查工具：已确认缺少时阻止保存；离线、旧版或上报超过 3 分钟视为「未确认」，允许保存。该检查只确认可执行文件存在，不能代替内核模块、权限、运行健康或业务连通性检查；需要更新 Agent 才能上报。
- 逻辑规则流量汇总各入口上报，每个入口只计算一次；移除入口仍保留历史用量，重置逻辑规则流量时一并清除。
- 速率限制按每个入口节点执行，不是跨机器共享一个总速率；主机流量达量排除策略继续适用。
- 删除被端口转发引用的入口组前，需先修改或删除引用资源。入口组关闭时关联规则停用，再开启时恢复受控关闭的规则。

### 运行诊断日志

- 面板 `[AgentTools]` 记录工具首次上报和变化，同主机至少间隔 60 秒；`[PortEntrySync]` 记录同步错误变化与恢复，`[PortEntryRetry]` 持续失败摘要每资源最多 15 分钟一次。
- 原有 `[Rule]` 状态日志增加 Agent 上报的连续失败次数和最早重试时间，重复相同运行状态的故障最多 5 分钟一次，恢复/启动状态变化单独记录。
- Agent 记录工具首次检测与变化、期望状态重试汇总（最多 5 分钟一次）及失败后恢复（同动作最多 5 分钟一次）。日志仅补充工具名、资源标识与计数，不输出新增凭据或完整配置。

### 资源流量汇总

链路管理的资源卡片和列表展示当前关联规则的**累计流量、入向、出向**。端口转发、转发组和转发链汇总各自的逻辑规则；入口组汇总显式引用它的端口转发、转发链及隧道规则，出口组汇总显式引用它的隧道规则。不统计同主机上的无关规则，也不将链路每一跳重复累加。

隧道、转发链、入口组和出口组同时显示「引用规则」数，按逻辑规则去重：同一规则的多入口或派生规则只算一条，停用规则仍计入，待删除规则不计入。经转发组间接使用隧道的规则也计入对应隧道及其入口/出口组；尚未生成运行时规则时，已保存的引用仍会显示。管理员统计全部关联用户，普通用户只统计自己的规则，不展示其他用户的引用数或流量。

累计流量为实际入向与出向之和，不使用计费倍率或单向计费方式折算。多个入口独立产生的流量各计算一次；入口移除后保留尚存逻辑规则的历史用量，重置规则流量后汇总同步更新。已删除规则不再计入当前资源汇总。管理员查看所有关联用户的用量，普通用户仅查看自己的规则用量。

## 出口组

出口组将多个出口主机保存为一个隧道出口资源，支持以下能力：

- **出口复用**：多条隧道共用同一组出口，统一管理。
- **故障转移**：某出口主机离线时，自动切换到组内其他成员。
- **多出口负载均衡**：流量分散到多个出口节点，降低单点压力。

规则列表中显示出口组名称，并可展开查看实际使用的出口节点，不再以第一台主机名称替代出口组名称。

---

## 入口组 vs 出口组

| 维度 | 入口组 | 出口组 |
|------|--------|--------|
| 用途 | 统一管理多个入口主机 | 统一管理多个出口主机 |
| 引用方 | 普通端口转发 / 隧道入口 / 转发链 | 隧道出口 |
| DDNS 支持 | 支持（可选） | 不适用 |
| 负载均衡 | 不适用 | 支持 |

---

## 状态说明

组成员及组整体都有独立状态：

| 状态 | 含义 |
|------|------|
| 在线 | 成员 Agent 与面板保持连接 |
| 已启用 | 组配置开关已打开 |
| 可用 | 由成员在线状态与最近探测结果共同决定 |

> “在线”不等于”可用”——Agent 在线但端口不通时，仍会被探测标记为不可用。

拖动成员可调整优先级，保存后会刷新引用关系。

---

## 命名建议

组名应能直接区分用途，便于在规则列表中快速识别：

- 入口组：`香港入口`、`新加坡入口-BGP`
- 出口组：`日本出口`、`美国出口-住宅IP`
- 转发组：`游戏入口故障转移`、`主站高可用入口`
