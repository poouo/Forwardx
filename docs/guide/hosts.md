# 主机管理

主机管理用于查看和维护所有已接入的 Agent 主机。

添加、修改、删除主机和隧道，以及 Agent Token 管理均仅限管理员；后端接口同样校验权限。普通用户仍可使用管理员授权的资源管理自己的转发规则。Agent 通讯只接受启用的管理员所创建的主机或 Token，历史普通账号创建的凭据会被拒绝，记录保留以供审计。管理员降为普通用户或停用时，其名下 Agent 凭据也失效；需继续使用的主机请由有效管理员重新接入。

## 主机列表

主机列表展示每台主机的实时状态，包括：

- **在线/离线状态** — 绿色表示在线，红色表示离线。
- **延迟** — 面板与 Agent 之间的往返延迟，反映连接质量。
- **Agent 版本** — 当前运行的 Agent 版本号。
- **CPU、内存、磁盘占用** — 主机资源使用情况。
- **系统负载** — 展示 1/5/15 分钟平均负载，例如 `0.12 / 0.25 / 0.38`。精简卡片悬停 CPU 查看，标准卡片在 CPU 区域展示，列表可单独启用「负载」列；需更新 Agent，未上报时显示 `—`。
- **公网 IPv4 / IPv6** — Agent 检测到的公网地址。
- **内网 IP** — 主机内网地址。
- **网卡信息** — 网络接口列表。
- **转发状态** — 当前转发规则的运行情况。
- **流量数据** — 累计上下行流量统计。

### 自定义列表

切换到「列表视图」，点击表头最左侧的列表设置图标，可勾选显示列、拖动调整列顺序或恢复默认。拖动表头右侧分隔线调整列宽，双击恢复该列默认宽度；聚焦分隔线后也可用方向键调整，Home 恢复默认。

名称、状态、地区、主地址、Agent 版本、负载、运行时间、到期时间、CPU、内存、磁盘和各类流量均拆为独立列。名称和操作必须保留；默认隐藏版本、负载、运行时间、到期时间和系统累计，可按需打开。名称不再堆叠状态与主机详情，列表行高更紧凑，长内容悬停查看完整信息。

设置按当前账号保存，刷新或更换设备后恢复；不会改变其他账号、规则列表或卡片视图。名称和操作列随表格一起横向滚动，不额外固定或覆盖其他列。

列总宽不足时，最后一个可见列自动补齐剩余空间；超出容器时保留横向滚动，不挤压已设置的列宽。

## 多 IP 与主地址选择

更新 Agent 后，在「编辑主机 → 基本信息 → Agent 检测 IP」分别选择 **IPv4 主 IP** 和 **IPv6 主 IP**。同一主机的多个公网 IPv4、IPv6 会各自汇总为下拉选项；默认自动选择，也可分别固定一个地址。

- Agent 检测已启用网卡上绑定的公网地址，并保留公网出口探测，约每分钟刷新缓存。过滤私网、回环、链路本地地址；系统支持读取地址状态时优先使用稳定 IPv6，忽略网卡的临时/废弃 IPv6，没有稳定地址时仍可回退到公网出口探测。
- 已选地址仍在检测列表时，后续上报不会覆盖选择；地址消失则回退到可用地址，重新检测到原地址后自动恢复原选择。
- 主 IP 用于面板中的默认入口与关联链路地址，不会修改操作系统网卡、默认路由或出站源地址。手动填写的入口/隧道入口地址仍优先。
- 商家只做 NAT 映射、没有绑定到系统的额外公网 IP 无法可靠自动发现；系统已绑定的公网别名地址可自动发现。旧 Agent 仍可上报单地址，多地址发现需升级 Agent。
- 管理员和主机所有者可以修改主地址，单纯获得资源使用授权的用户不能修改。

DDNS 可选择仅同步两类主 IP，或同步对应协议的全部检测地址，详见 [DDNS 配置](./ddns.md#主机多-ip-与双栈)。

## 在线与离线

绿色表示在线，红色表示离线。

如果主机离线，常见原因：

- Agent 服务没有运行。
- Agent 配置中的面板地址不对。
- 面板域名、端口或反向代理不可访问。
- 服务器防火墙阻止连接。
- 面板公开地址修改后，Agent 还在使用旧地址。

在 Agent 主机上可以查看日志排查：

```bash
journalctl -u forwardx-agent -n 300 --no-pager
```

Agent 配置文件位于 `/etc/forwardx/agent/config.json`，日志目录位于 `/var/log/forwardx-agent/`。

### 上下线通知

管理员可在「编辑主机 → 其他配置」设置「上下线通知」，新建主机和已有主机默认开启。实际推送仍需在系统设置启用所选通知渠道（Telegram / Discord）及主机上下线通知，并由管理员绑定对应账号。

关闭期间不再推送该主机的上线、离线消息，发送前也会检查开关以屏蔽排队中的离线提醒；不影响在线状态、离线历史、故障转移及流量/续费提醒。重新开启不会主动补发已跳过的消息。

## 主机信息维护

建议给每台主机填写清晰的名称，例如：

```text
香港入口-1
日本落地-1
美国中转-1
```

也可以设置：

- **备注** — 记录主机用途或额外说明。
- **手动入口 IP 或域名** — 覆盖自动检测的公网地址。
- **DDNS 域名** — 绑定动态域名，支持 DDNS 故障转移。
- **网卡名称** — 指定流量统计所使用的网卡。

主机名越清楚，后续创建转发规则、隧道和链路时越不容易选错。

## 用户授权与主机可见性

在「用户管理 → 授权」分别配置端口转发、转发链/转发组和隧道的使用权限，不以是否分配成员主机代替资源授权。普通用户可能通过有效套餐或按量计费产品获得使用权限，不一定需要逐台手动授权。

网络测试的主机列表另外受主机权限控制：用户自有、通过主机授权或有效套餐授权获得的主机可见；仅有链路使用权限，不会让其成员主机单独出现在网络测试中。管理员可管理全部主机。

完整操作及撤销授权后的规则行为见 [用户、套餐和权限](./users-billing.md#权限分配)。

## URL 连接检测

在「主机管理 → 服务管理 → 添加/编辑服务 → 常规探测」选择「URL 连接检测」。填写完整的 HTTP/HTTPS 地址、超时（1–30 秒，默认 5 秒）和预期状态码（默认 200），再选择运行主机与检测间隔。例如检测 `https://example.com/health` 返回 204 时，将预期状态码设为 `204`。

- 每次由选中主机的 Agent 发起一个新的 GET 请求，计入 DNS、TCP 建连、HTTPS 握手和等待响应首字节的耗时；不复用连接、不使用系统 HTTP 代理、不跟随重定向，也不等待完整下载响应内容。
- HTTPS 校验证书，证书错误、超时、连接失败或状态码不符均计为检测失败；如需检测 301/302 本身，可将其设为预期状态码。
- 结果进入现有服务延迟图表，失败比例表示请求失败率，不是 ICMP 丢包率。
- 这是主机出口检测，不自动经过某条转发规则或隧道，也不代表游戏 UDP 延迟。请选择允许周期性 GET 的健康检查地址，不使用会产生业务操作的接口。
- 需要更新 Agent；旧 Agent 不执行 URL 检测，不会退化为 TCP 检测后误报成功。URL 不支持内嵌账号密码，勿在地址查询参数中放置密钥。

国内健康检测仍仅使用 Ping/TCPing，防止网站维护或证书问题误触发自动换 IP。

## 国内健康检测与自动换 IP

入口：管理员进入「主机管理 → 服务管理 → 添加/编辑服务」，在顶部左右选项中选择「常规探测」或「国内健康检测」，默认常规探测。国内健康检测每项只选择一台主机，目标填写稳定的国内**固定公网 IP**，方法可选 TCPing（需端口）或 Ping（ICMP）。选中后显示专属的异常判定、通知和自动换 IP 配置，不再使用底部开关切换模式。检测由所选主机发起，不是由面板服务器发起。

服务管理只维护配置。检测状态和换 IP 记录统一在「运维看板」底部的「状态与告警记录」查看。

默认同时满足「连续失败 3 次」和「失败持续 120 秒」才判定异常，连续成功 2 次恢复。采样中断后重新积累失败次数；服务暂停或删除后不再触发新动作。检测间隔须为 5–300 秒。

::: warning 检测结论
探测失败也可能是目标维护、禁止 ICMP、端口关闭、路由故障等原因，不能单凭一次出站探测确认 IP 被墙。界面显示“疑似国内连通异常”，达到设定条件后仍会直接执行你开启的后续操作，**不等待人工或 AI 回复确认**。请选择可靠目标并合理设置判定时长，避免误触发付费换 IP。
:::

### 通知与商家接口

- 「通知管理员」默认开启，自动通知已绑定当前 Telegram / Discord 通道的启用管理员，无需选择接收用户。关闭后仍记录日志；旧配置中的自定义接收用户不再生效。
- 「自动切换 IP」默认关闭。启用前核实商家费用、重启影响和接口是否允许从该主机访问。
- 必须同步更新目标主机的 Agent；不支持该功能或近期没有有效心跳时，面板提示不可用，不会改由面板代发请求。

商家给每台 VDS 提供内网管理通道时，例如：

```text
http://10.0.0.1/api/changeip?token=你的商家令牌
```

在接口地址填写商家提供的**实际内网地址**，请求方法选择 `GET`，无需安装或执行 curl 脚本。任务仅通过加密通讯发给被检测主机的 Agent，由该 Agent 原生发送 HTTP 请求。支持 HTTP / HTTPS、GET / POST / PUT、自定义请求头和请求体；HTTP 只建议用于可信内网，公网请用 HTTPS。禁止跳转、环境代理及本机环回、链路本地/云元数据等受限目标；内网私有管理地址可用。

可用占位符：`{{hostId}}`、`{{serviceId}}`、`{{ip}}`、`{{incidentId}}`。其中 `ip` 为主机当前入口地址；令牌不要放到通知文案或公开截图中。

接口结果可选两种判断方式：

- **HTTP 2xx：请求已接收**：适合只有一条 GET 请求、暂未提供响应结构的商家。仅记录接口接收请求，不声称已经换好 IP，实际结果以后续探测和商家状态为准。
- **JSON 字段严格匹配**：有响应文档时推荐。例如返回 `{"success":true,"data":{"ip":"新公网 IP"}}`，成功字段填 `success`，预期值填 `true`。布尔值 `true` 与字符串 `"true"` 不等价。

如需同步面板地址，填写新 IP 的 JSON 路径（上例为 `data.ip`），选择更新主机入口或同时更新隧道入口；只接受与旧地址不同的有效公网 IP，并刷新关联链路。异步换 IP 接口不自动轮询商家任务：未返回新 IP 时选择“不修改面板地址”。**未手动指定入口地址**的主机可等待 Agent 重新上报；手动指定过的地址仍需自行更新。不要把更新主机入口误认为会更改商家网络或其他服务的出口配置。

### 自动执行保护与排查

在服务的国内健康检测配置中设置「商家换 IP 间隔（分钟）」，默认 **60 分钟**，可按商家要求调整为 5–1440 分钟；该值由管理员填写，不依赖商家接口返回。间隔从上次请求完成后计算，多项服务共用同一主机的请求历史。重启面板、删除重建服务，或改用更短间隔的另一项服务，都不会缩短已经开始的等待时间。默认滚动 24 小时最多请求 3 次。

同一异常下，商家已接收、已确认成功或结果不明的请求不自动重发；只有明确「Agent 未执行」的任务，才会在商家间隔结束且仍持续异常时使用新的任务 ID 重新调度，仍受每日上限限制。面板先保存请求意图，Agent 在本地持久化防重复标记，再调用商家。超时、断联或面板/Agent 重启后不会自动重发可能已经执行的付费请求。

接口结果不明确时停止该主机后续自动换 IP，管理员核对商家任务是否结束后，可在「运维看板 → 状态与告警记录 → 国内健康检测」使用「已核对商家结果」解除保护；按钮至少等待 150 秒才可用。此操作**仅处理异常结果，不是正常执行前的审批**，也不会重发原请求。同一主机另一项服务也可查看和解除遗留保护，删除服务不会抹掉请求历史。

如果收到异常通知却没有换 IP 通知，先核对服务是否启用了「自动切换 IP」并配置了接口，再到「运维看板 → 状态与告警记录」查看：国内健康检测页会展示 Agent 能力、等待商家间隔、每日上限或上次未知结果等原因，以及下次最早请求时间；IP 更换记录会展示接口配置错误、任务过期、连接失败、HTTP 状态、成功字段不匹配或新 IP 无效等分类。仅有 HTTP 2xx 不代表商家实际换 IP 成功。

Agent 日志搜索 `IP switch task=`，面板日志搜索 `[ChinaHealth]`，使用相同的 `task` ID 关联一次任务。升级 Agent 后，可按以下阶段定位：

| Agent 日志 `stage` | 含义 |
| --- | --- |
| `received` | 已收到任务，附剩余有效秒数 |
| `claim_started` / `claim_finished` | 向面板校验是否允许执行；检查 `allowed` 和 `error` |
| `execution_skipped` | 本次未请求商家接口；检查过期、去重、状态文件或校验失败原因 |
| `request_started` | 开始 HTTP 请求，附方法、成功判断模式和超时秒数 |
| `tls_finished` / `request_written` | TLS 握手或本地请求写入结果；写入成功不等于商家执行成功 |
| `response_received` / `request_finished` | HTTP 状态、响应类型、校验结果及耗时 |
| `result_reported` | 面板明确接收了结果 |
| `result_report_failed` / `result_report_rejected` | 回传失败或面板未接收结果，不会因此重新请求商家接口 |

例如 `diagnostic=response_not_json responseFormat=html` 表示要求 JSON 校验，但接口返回了 HTML；`redirect_not_followed` 表示接口要求跳转，Agent 为避免重复操作不会自动跟随；`dns_failed`、`connection_refused`、`timeout`、`tls_certificate_invalid` 分别指向解析、连接、超时或证书故障。`http_accepted_not_verified` 只代表 HTTP 2xx，不证明实际换 IP。结果不明时先核对商家记录，不要反复手动访问可能收费的接口。

日志不记录接口地址、令牌、请求体或商家原始响应。接口凭据加密保存、编辑时不回显；只更改检测参数会保留原凭据，替换接口需重新填写完整配置。数据库迁移合并不自动移植这类自动操作配置；更换 JWT 密钥后也需重新填写接口，避免误用旧凭据。

## NAT 主机与可用端口

NAT 主机应在主机配置中填写供应商实际映射的可用端口范围，TCP / UDP 分别按供应商能力放行。范围配置只限制面板分配，不会替你创建供应商的 NAT 映射或修改安全组。

业务入口、隧道承载监听与部分模式的规则出口监听可能是不同端口。需要规则独立出口端口的模式会占用额外端口；不要把“隧道测试通”当作业务端口已经映射。Nginx Stream 隧道规则复用该隧道的监听端口；变更模式后检查实际规则端口与运行状态。

## 流量故障转移

在主机编辑的「其他配置」设置大于 0 的套餐流量、计量方式，再开启「流量故障转移」并设置阈值（1%–100%）。达到阈值后，主机暂停参与转发组、入口组和出口组调度，不删除组成员，也不改变 Agent 在线状态。

计量按当前周期的主机流量与所选方式计算，见 [流量口径](./traffic-latency.md)。重置流量、提高额度使其低于阈值，或关闭开关后重新参与调度；恢复依赖面板重新计算与 Agent 同步。没有可用备用成员时，排除主机并不保证业务可继续，需提前配置备用路径。

此开关不是单条规则额度或账户额度，也不是主机断电开关；不要用它代替 [单规则限额](./rules.md#单条规则限额与有效期)。

## 流量耗尽关机

管理员可在「其他配置」开启「流量耗尽关机」（默认关闭），设置已用流量阈值 1%–100%，默认 100%。需要先填写大于 0 的套餐流量，并更新 Agent；仅支持以 root 运行的 Linux Agent。统计沿用主机的「流量计算」设置，与流量故障转移、通知渠道互不依赖。流量和续费提醒分区并排展示，各自保留开关及阈值；未配置通知渠道时开关禁用，悬停或键盘聚焦可查看原因。流量提醒按剩余比例，流量关机按已用比例计算。

**达到阈值会关闭整台机器，中断所有服务，不只是停止转发。** 开启时会要求确认，保存后生效；若当前用量已达阈值，下次心跳即可触发。请确保能通过服务商控制台手动开机，面板不会自动开机。检测依赖面板连接及 Agent 上报，并非断网时的本地流量硬限制，不能保证精确卡在阈值处。

执行前会再次核对当前开关、额度、阈值和最近两分钟的流量上报，同一统计周期只授权一次，面板或 Agent 重启后也不会反复关机。手动开机不会重新触发；手动/每月流量重置后重新计量，或将关机开关关闭并保存、再开启保存，才会重新启用本周期触发。用量修正、修改阈值和普通保存不会清除已触发标记。若关机命令失败或授权响应丢失，为避免循环关机也不会自动再次授权；可检查 Agent 日志中的 `[HostTrafficShutdown]`，排除问题后重新开关。界面「本周期已触发」表示已授权执行，并不等于确认物理关机成功。

## 用量修正

管理员在主机操作菜单选择「用量修正」，弹窗默认填入当前统计的已用流量。核对主机和当前计量方式，输入修正后的总用量（GB，不能小于 0），点击「保存修正」。输入的是新的累计值，不是本次增减量。

后续上报在修正后的用量上继续累计。此操作只修正面板的主机累计用量，不修改 Agent 系统累计流量，也不替代用户流量重置或账务退款。若开启了流量故障转移，修正后还应核对是否达到调度阈值。

## 安全移除主机

先从转发组、转发链、入口组 / 出口组与隧道中移除对应成员。保存成员变更会同步模板引用，未改变的健康成员规则保留；仍有真实依赖时，删除弹窗会列出关联资源及处理入口。

在线主机需等 Agent 完成清理；离线清理必须明确确认，不会绕过真实依赖。若只修改了业务目标而未移除资源成员，仍不能直接删除主机。

## 主机排序

主机管理中的排序通过拖动完成，不需要手动填写排序数字。

- **无分组时** — 在主机列表中直接拖动调整顺序。
- **有分组时** — 「全部」视图按分组顺序汇总展示，不支持直接拖动。切换到具体分组后，只调整该分组内的主机顺序。
- 主机分组、Agent Token 和主机探测服务也支持拖动排序。

## mimic 环境检测

mimic 是基于 eBPF 的 UDP 混淆方案（来自 [hack3ric/mimic](https://github.com/hack3ric/mimic)，GPL-2.0-only，当前版本 v0.7.1），需要满足特定的内核与权限条件。面板会自动检测每台主机的 mimic 运行环境，并在主机列表中显示检测结果：

| 状态 | 含义 |
|------|------|
| 支持 | 内核版本 ≥ 6.1，XDP 入站和 TC 出站 eBPF 钩子可用，可正常使用 mimic |
| 内核版本不足 | 当前内核版本低于 6.1，不支持所需的 eBPF 特性 |
| eBPF 不可用 | 系统未加载必要的 eBPF 模块或缺少相应权限 |
| 未检测 | Agent 版本过旧或检测尚未完成 |

如果需要使用 mimic UDP 混淆功能，请确保主机内核版本不低于 Linux 6.1，并确认 XDP 入站和 TC 出站 eBPF 功能可用。Agent 会在 XDP `native` 与 `skb` 模式之间自动回退，无需在面板手动切换。

## IPv6 检测

如果 IPv6 地址检测不到，先确认服务器自身是否有可用 IPv6：

```bash
ip -6 addr show scope global
ip -6 route
ping -6 -c 4 2606:4700:4700::1111
```

如果服务器只有内网 IPv6 或 IPv6 不可出站，面板可能无法将其作为可用入口展示。
