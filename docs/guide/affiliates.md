# 推广返佣（AFF）

默认关闭。在「推广管理 → 右上角设置」开启「启用推广返佣」，调整返佣参数后点击「保存设置」。取消或关闭弹窗不会保存修改。

「系统设置 → 左侧导航栏菜单展示设置 → 推广管理」统一控制管理员和普通用户的侧边栏入口，不影响邀请绑定和订单计佣。首次升级时业务总开关继承原菜单开关状态，之后两者独立保存。关闭菜单后，有历史推广账务也不再显示入口，但仍可通过原页面地址查看有权限的历史记录；管理员可访问 `/affiliate-management` 管理设置。

- 普通用户：侧边栏「推广返佣」，位于账单中心之后、工单支持之前。
- 管理员：侧边栏「推广管理」，位于账单与兑换之后；业务功能关闭时仍可管理历史账务，菜单是否显示由上述菜单开关控制。

## 邀请与返佣

用户可创建多个邀请码、复制注册链接或邀请码、生成二维码，查看邀请人数、待确认和可用佣金、邀请记录及佣金流水。邀请码可停用，停用不影响已经建立的邀请关系。

注册页自动读取链接中的 `ref`，也可手动填写邀请码。浏览器保存邀请信息 30 天；新的有效格式邀请码会覆盖之前的记录。邮箱注册和 Google 首次注册均支持；现有账号登录、Google 绑定不会补绑或更换邀请人。邀请码不存在、已停用，或推广系统关闭时，注册正常完成但不建立邀请关系。

计佣范围：**在线支付、CNY 币种、已完成的套餐订单实付金额**。折扣后的实付金额参与计佣，金额按分向下取整。充值、余额购买、流量包、赠送、兑换、测试订单及其他币种不计佣，避免重复计佣和循环套取佣金。没有点击量追踪，不采集受邀用户的额外设备信息。

管理员可在右上角设置弹窗中配置：业务总开关、默认比例、仅首单或持续返佣、确认天数、最低提现金额、每人邀请码上限、是否允许转余额；也可以在推广用户列表中为账户设置独立比例（包括 0%）或停用账户。设置调整只影响后续生成的佣金，不重算历史记录。

默认比例 15%、仅首单、确认期 7 天、最低提现 10 元、允许转余额、每人最多 10 个邀请码。首单以成功完成的在线套餐订单为准；在系统关闭或返佣比例为 0 时完成的首单，不会因以后启用而把续费变成首单。

## 结算与提现

支付完成与生成佣金使用同一数据库事务；订单号唯一，支付重复回调不会重复返佣。确认期结束后由后台维护任务自动结算，查询或操作佣金时也会结算已到期记录。

佣金独立于账户余额：

- 提现支持支付宝、微信、银行卡收款信息；申请时先扣留金额，每人最多 5 笔待审核申请。
- 管理员**在线下实际打款后**填写交易凭证并确认已打款；系统不会调用支付接口自动转账。
- 驳回申请会原额退回可用佣金，重复审核不会重复退款。
- 转入账户余额后只能消费，不能再提现。余额增加与佣金扣除使用同一事务，重试不会重复到账。
- 收款信息只对申请人和管理员可见，不生成公开链接；备份包含这些信息，请妥善保存。

## 退款、冲正和关闭

目前面板没有统一的支付退款事件接口。**管理员在支付平台退款后，必须在推广管理中取消对应返佣**，不会自动识别外部退款。

- 待确认佣金：直接取消，不增加可用佣金。
- 已确认佣金：按原金额冲正，保留原因和流水。
- 若佣金已经提现或转入余额：可能形成负数佣金余额，后续佣金先抵扣欠款；欠款未清时禁止新增提现和确认打款。不会擅自扣除普通账户余额或撤销已完成的银行转账。

关闭系统后停止新增邀请绑定、创建/启用邀请码及订单返佣；已有邀请关系和账务保留，历史用户仍能打开入口、查询和申请提现/转余额，管理员仍能审核、冲正。停用单个推广账户则同时禁止其新增返佣、提现、转余额和打款，管理员可驳回待处理提现。

## 备份与验证边界

SQLite / MySQL / PostgreSQL 启动时自动创建六张 `affiliate_*` 表，纳入完整与精简备份、数据库切换和迁移。迁移会重映射用户及账务引用；已删除用户的历史记录不关联到其他真实用户。

为避免两个面板合并时重复计佣、余额与流水不一致，含推广账务的备份要求目标没有推广数据；不支持向已有推广账务的目标增量合并。请导入空目标或先完整备份后使用新的数据库，勿直接手工删除账务表。

自动化测试覆盖真实 SQLite 账务事务、权限、重复回调、确认期、提现、余额划转及冲正。MySQL / PostgreSQL 的真实实例仍需部署环境验证；建议先小额验证支付、提现与外部退款流程。
